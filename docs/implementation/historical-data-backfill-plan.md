# 历史行情入库与增量同步方案

日期：2026-05-29

## 当前状态

华为云生产库当前状态：

- `market_quotes`：约 5525 条，属于当前/近实时行情快照。
- `stock_basic_info`：约 5525 条，属于股票基础信息。
- `stock_daily_quotes`：0 条，历史日线尚未初始化。
- `stock_news`：约 30 条，新闻数据覆盖很低。

结论：当前不能认为历史行情已经入库。监控系统可用 `market_quotes` 判断当日异动，但 20 日新高、60 日低点反弹、持续上涨/下跌等趋势判断需要先补齐 `stock_daily_quotes`。

## 目标

第一阶段只做 A 股日线数据入库，先服务监控筛选，不做分钟线、不做全量研报、不做复杂因子库。

- 初始化 `stock_daily_quotes`。
- 后续按交易日增量更新。
- 当前行情继续写入 `market_quotes`。
- 监控分析优先读数据库，只有缺口才调用外部数据源补齐。
- 所有外部接口调用必须有速率限制、失败重试、断点续跑和入库验收。

## 数据源选择

### 主数据源：TuShare

优先用于日线历史数据。原因：

- 官方对 A 股日线 `daily` 接口有明确权限、频次和单次数据量说明。
- 支持按股票或按交易日拉取。
- 适合做稳定的批量历史初始化和每日增量。

官方规则参考：

- 积分与频次：`https://tushare.pro/document/1?doc_id=290`
- A 股日线：`https://tushare.pro/document/2?doc_id=27`

### 可选增强：Wind 一次性补库，TuShare 后续增量

如果开通 Wind API，可以把第一阶段数据源策略调整为：

- Wind 用于一次性补齐历史行情、公告、新闻舆情、行业/公司基础面等存量数据。
- TuShare 用于后续每日新增行情和可覆盖的基础数据增量。
- AKShare 仍作为补缺、对账和应急兜底源。

不建议把 AKShare 作为 Wind 历史补库后的主增量源。原因是 AKShare 底层聚合东方财富、新浪等第三方站点，字段、频控和可用性不如付费/权限型数据源稳定。对于同一类核心数据，优先级应为：

1. 最优：Wind 历史 + Wind 增量，来源最一致，但成本和授权要求最高。
2. 推荐折中：Wind 历史 + TuShare 增量，AKShare 只补缺和对账。
3. 低成本但风险较高：Wind 历史 + AKShare 增量，必须做严格对账和 `coverage_gap` 标注，不建议作为正式主链路。

这个方案在架构上可行。当前历史行情集合 `stock_daily_quotes` 的唯一键包含 `data_source`，可以保留 `wind`、`tushare`、`akshare` 等来源标记，不需要把 Wind 数据伪装成 TuShare 数据。后续监控查询应优先读取统一后的标准字段，必要时按数据源优先级选择：

1. 同一股票同一交易日有 Wind 和 TuShare 数据时，价格行情以主数据源优先，差异超过阈值进入对账异常表。
2. 历史补库完成后，Wind 不再作为默认每日行情源，除非后续继续购买并确认授权允许生产增量。
3. 新闻、公告、研报、舆情数据必须保留来源、发布时间、原始链接、采集时间和供应商权限信息，避免把不同授权级别的数据混在一起。

官方资料参考：

- Wind Client API：`https://www.wind.com.cn/mobile/ClientApi/zh.html`
- Wind 数据接口服务：`https://www.wind.com.cn/mobile/WDS/sapi/zh.html`
- Wind 行情服务：`https://www.wind.com.cn/mobile/WDS/marketdata/en.html`

开通前必须向 Wind 确认：

- 是否支持当前部署环境。Wind Client API 支持 Windows、Mac、Linux、银河麒麟和 Python/MATLAB/R/C++/C#/VBA，但具体账号授权、安装包、登录方式和云服务器使用限制需要以合同和技术支持为准。
- 是否允许把历史数据落入自有 MongoDB，并用于本项目的监控、分析和模型输入。
- 是否允许自动化批量补库、批量频次是多少、是否有日调用量或并发限制。
- 需要购买哪些具体数据包：A 股历史日线、复权因子、财务数据、公告、新闻舆情、研报/盈利预测、行业分类和指数成分。
- 资讯、公告、研报正文是否允许长期存储；如果不允许，应只存元数据、摘要、链接和供应商标识。

### 备用数据源：AKShare

用于 TuShare 不可用、个别股票缺口、非关键字段补齐。AKShare 官方文档覆盖股票实时行情、历史行情等数据接口，但它聚合多个第三方站点，公开文档没有给出统一、稳定的官方频次配额。

官方文档参考：

- AKShare 文档首页：`https://akshare.akfamily.xyz/`
- AKShare 数据字典：`https://akshare.akfamily.xyz/data/index.html`

### 暂不作为第一阶段主源：BaoStock

BaoStock可作为低频兜底源，但第一阶段先避免三源同时写历史库导致质量核对复杂化。

## 速率与总量限制

### TuShare

按官方文档，TuShare Pro 是权限分层：

- 积分接口：日线、基础数据等受积分门槛、每分钟频次、每天总量限制约束。
- 独立权限接口：分钟、新闻舆情、公告、券商研报等需要单独开权限。

A 股日线 `daily` 官方说明：

- 交易日每日 15:00-16:00 入库。
- 日线接口页说明可按股票或按交易日拉取，并给出较高的接口能力上限。
- 每次最多 6000 条。
- 一次请求相当于提取一个股票 23 年历史。

通用积分表按账号积分分层限制频次和总量：

- 120 积分：50 次/分钟，日总量 8000 次，仅股票非复权日线。
- 2000 积分以上：200 次/分钟，100000 次/个 API。
- 5000 积分以上：500 次/分钟，常规数据无总量限制。
- 新闻资讯、公告、券商研报等属于独立权限，不等同于普通积分接口。

因此实际执行必须以账号在 TuShare 后台显示的权限为准。接口页能力上限不等于当前 token 一定可用的执行额度。

实施约束：

- 在确认账号真实权限前，不按项目默认 `standard` 跑全市场。
- 第一阶段保守设置为 30-60 次/分钟。
- 每 100 只股票写入一次进度。
- 出现权限、限流、429、请求过于频繁等错误，自动降速并暂停批次。

### AKShare

AKShare 官方文档列出了大量数据接口，但没有统一的全局调用频次和总量额度。由于其底层数据来自东方财富、新浪、雪球等站点，实际限制通常由第三方站点反爬、IP 频控和接口稳定性决定。

实施约束：

- 不并发批量拉取 AKShare 历史数据。
- 默认 1 次/秒以内，失败后指数退避。
- 只用于补缺和对账，不作为首轮全市场历史初始化主通道。
- 不使用代理、绕过风控或非官方技巧。

## 入库模型

历史日线统一入库：

- 集合：`stock_daily_quotes`
- 唯一键：`symbol + trade_date + data_source + period`
- 周期：第一阶段只写 `daily`
- 市场：第一阶段只写 `CN`
- 字段：open、high、low、close、pre_close、change、pct_chg、volume、amount、trade_date、data_source、period

当前行情继续入库：

- 集合：`market_quotes`
- 用途：盘中当前价格、单日涨跌、成交量快照
- 行为：反复 upsert 覆盖，不承担历史序列职责

## 初始化策略

### 推荐范围

默认先初始化最近 3 年 A 股日线。如果已开通 Wind 且授权允许批量历史落库，可以把初始化范围扩展为最近 5-10 年或更长，但必须先做小样本对账。

原因：

- 足够支持 20 日、60 日、120 日趋势判断。
- 数据量可控。
- 比一次拉 20 多年全历史更容易发现和修复质量问题。

估算：

- 约 5500 只股票。
- 3 年约 730 个交易日。
- 理论记录量约 400 万条以内。

### 执行顺序

1. 备份 MongoDB。
2. 确认 `stock_basic_info` 股票列表完整。
3. 确认主数据源权限：TuShare token、积分、日线权限；如果使用 Wind，则确认 Wind 授权范围、批量频次、落库权利和部署环境。
4. 小样本试跑 20 只股票，范围最近 90 天。
5. 核对记录量、字段、日期格式、单位转换。
6. 如果使用 Wind 补库，用 TuShare/AKShare 对样本股票最近 60 个交易日进行交叉对账。
7. 扩大到 300 只股票，范围最近 1 年。
8. 全市场最近 3 年初始化；Wind 授权允许时再扩大历史年限。
9. 初始化完成后运行监控扫描，确认趋势类信号不再因为历史数据缺失而失真。

## 增量策略

每日收盘后执行：

- 时间：A 股收盘并等待数据源更新后，建议 17:30-18:30。
- 范围：全市场或 watchlist + 活跃异动池。
- 起点：每只股票 `stock_daily_quotes` 中最新 `trade_date + 1`。
- 终点：当前交易日。
- 写入：upsert。
- 成功后可将最新交易日收盘数据回填到 `market_quotes`，作为休市期间的当前快照。
- 默认增量源：TuShare。
- 兜底源：AKShare；如果继续购买 Wind 增量权限，也可配置为最高优先级，但必须遵守 Wind 授权和频次限制。

## 质量校验

每次初始化或增量同步后必须检查：

- `stock_daily_quotes` 总记录数。
- 按 `data_source`、`period`、`market` 分组数量。
- 最新交易日覆盖股票数。
- 样本股票最近 60 条是否完整。
- `volume` 和 `amount` 单位是否统一。
- 是否存在同一 `symbol + trade_date + data_source + period` 重复。
- 是否存在 `close <= 0`、`trade_date` 为空、`symbol` 为空。
- 监控服务扫描 watchlist 时是否能读到 K 线。

## 第一阶段任务拆分

1. 增加历史数据初始化脚本，支持 `--source wind|tushare|akshare`、`--start-date`、`--end-date`、`--symbols`、`--limit`、`--dry-run`。
2. 增加同步状态表，记录任务进度、最后成功股票、失败股票、速率统计。
3. 增加数据质量校验脚本。
4. 增加小样本测试和质量门禁。
5. 在 staging 先试跑小样本。
6. 在生产执行 20 只、300 只、全市场三个批次。
7. 开启每日增量任务。
8. 更新监控逻辑：当历史数据缺失时在报告中明确标注 `data_gaps`，避免给出过度自信结论。

## 非目标

- 不做分钟线。
- 不做全历史 30 年一次性初始化。
- 不做绕过第三方站点风控。
- 不把 AKShare 作为高并发主数据源。
- 不把研报、公告、新闻权限和日线行情权限混为一谈。
